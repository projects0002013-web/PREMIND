# PREMIND

**Detect the decline before you feel it.**

Локальная исследовательская платформа для измерения реакции, внимания и выполнения когнитивных задач. Это экспериментальный инструмент, а не медицинский тест или доказанная система прогнозирования.

## Запуск

Node.js 22 или 24, npm. Для локального режима облачные ключи и регистрация не нужны.

```sh
npm ci
npm run dev
```

```sh
npm test
npm run typecheck
npm run build
```

Приложение использует React, TypeScript, Vite, React Router, Recharts, Framer Motion, Lucide и IndexedDB (`idb`). CSS — собственная адаптивная дизайн-система. Python/ML и Supabase не требуются для локальной работы.

## Возможности

- Пять реальных задач: зрительная реакция, Струп, Go/No-Go, воспроизведение цифр с выбором сложности, визуальный поиск.
- Обучение без сохранения, результаты с сырыми попытками, средним, медианой, выборочным SD и точностью.
- Research Lab: гипотеза, выбор тестов, 2–5 временных точек, перерывы, самооценки, случайный код участника и остановка в любой момент.
- История, фильтрация, выбор результатов для сравнения, графики, календарь, CSV и JSON, проверяемый импорт с подтверждением замены, удаление с подтверждением.
- Отчёты с таблицами и графиком. Кнопка «Сохранить PDF / печать» открывает системный диалог печати: выберите сохранение в PDF.
- RU/EN, светлая/тёмная тема, клавиатура, увеличенный текст, reduced motion, PWA с офлайн-кэшем сборки.

## Аккаунты и облачная база

Добавлены Google OAuth, вход/регистрация по email, подтверждение почты, восстановление пароля, выход и ручной перенос исследовательской базы через Supabase. Без настроенного проекта приложение полностью работает локально; вход не запускает загрузку результатов. Перед облачным сохранением требуется отдельное согласие и подтверждение. Обновление копий защищено сравнением ревизии, доступ — PostgreSQL Row Level Security.

Нужно создать проект Supabase, выполнить SQL из `supabase/migrations`, подключить Google и добавить публичные переменные сборки. Полная инструкция: [docs/CLOUD_SETUP.md](docs/CLOUD_SETUP.md). **Реальный проект Supabase и Google OAuth ещё не подключены.** Ни пароль базы, ни service_role, ни Google Client Secret нельзя добавлять в Vite или GitHub.

## Методика

Время отсчитывается через `performance.now()` в animation frame после отображения сигнала. Это браузерное приближение, а не аппаратный замер: задержки экрана, событий и устройства сохраняются. Скрытие вкладки отменяет текущую попытку. В Go/No-Go корректное воздержание включено в точность, но не в среднее время реакции. Для памяти измеряется время ввода после завершения показа цифр. Максимальный срок ответа — 10 секунд (15 для памяти), затем учитывается пропуск.

Baseline — первые три предшествующих результата одного теста, участника и устройства. Текущие и будущие данные исключены. Предварительные критерии: время правильных ответов +20% или точность −10 процентных пунктов. В Research Lab порог реакции задаётся до начала; первая точка — внутрисессионная опора, а не устойчивый baseline. Субъективное изменение — рост самооценки снижения концентрации на 2 балла. Отчёт о порядке изменений использует основной (первый выбранный) тест и оценки после серии. Критерии не являются клиническими нормами.

Сравнивайте одинаковую сложность памяти и одинаковые условия. Устройство обозначается локальным идентификатором браузера, не аппаратным fingerprint. Очистка хранилища создаёт новый идентификатор. Эффекты обучения и случайные колебания описаны как ограничения; статистической коррекции тренировки пока нет. Струп требует различения цветов.

Модель прогнозирования **не обучена**. Вероятности не выводятся. Будущий ML требует разделения выборок по участникам, исключения будущих данных, сравнения с простым baseline, precision/recall/F1/ROC-AUC и калибровки на отложенной выборке. Лабораторная валидизация и научная проверка протоколов остаются будущей работой.

## Данные и согласие

По умолчанию данные остаются в IndexedDB. При отдельном согласии пользователь может сохранить полную копию базы в Supabase через страницу аккаунта. Выход не очищает локальные результаты; удаление облачной копии и локальной базы выполняются отдельно. JSON — полная резервная копия, CSV — сырые попытки с псевдонимными кодами. Экспорт не гарантирует анонимность, если исследователь ввёл личные сведения в свободный текст. Для несовершеннолетних получите письменное информированное согласие представителя и разрешение школы. Отметка согласия в интерфейсе не заменяет документы.

При перезагрузке незавершённые сессии остаются в базе и в резервной копии, но не возобновляются: начинайте новый протокол. Ведите регулярные резервные копии — браузер может удалить данные. Импорт заменяет всю базу только после проверки и подтверждения.

## GitHub Pages

`vite.config.ts` использует `base: '/PREMIND/'`. HashRouter позволяет открывать внутренние страницы без настройки сервера.

1. Разместите файлы в `projects0002013-web/PREMIND`, ветка `main`.
2. В Settings → Pages выберите Source: **GitHub Actions**.
3. Workflow `.github/workflows/pages.yml` выполнит `npm ci`, тесты, сборку и публикацию.

PWA работает в production через HTTPS (или localhost). После загрузки и установки service worker сборка доступна офлайн. Меню браузера позволяет установить приложение на телефон; iOS использует «Добавить на экран Домой». После обновления приложения перезагрузите вкладку. Сам деплой из этой рабочей среды не выполнялся.

## Архитектура

`src/pages` — страницы и протокол; `src/components` — оболочка, тесты, графики, отчёт; `src/algorithms` — чистые расчёты; `src/storage` — IndexedDB, импорт и экспорт; `src/cloud` — Supabase Auth и операции облачных копий; `supabase/migrations` — SQL и RLS; `src/types` — контракт данных; `src/tests` — unit и интеграционные сценарии; `scripts/generate-sw.mjs` — офлайн-кэш с версией сборки.

## Проверка в настоящем браузере

При запущенном `npm run dev` выполните `npm run test:e2e`. Скрипт использует системный Chromium (`/usr/bin/chromium`); другой путь задайте через `CHROMIUM_PATH`, адрес сборки — через `PREMIND_BASE_URL`. Он проходит все пять тестов, проверяет сохранение после перезагрузки, исследовательский протокол, перерывы, самооценки, отчёт и мобильную ширину. Время в этом автоматическом сценарии симулируется: его результаты не являются данными исследования.

Офлайн-проверка production: после `npm run build` запустите `npm run preview -- --port 4173`, затем `npm run test:offline`. Скрипт ждёт управления service worker, отключает сеть и проверяет перезагрузку, навигацию и появление стимула.

Тесты облака проверяют UI согласия, контракты SDK и конфликты ревизий. `database.test.ts` запускает миграцию и проверяет RLS в настоящем PostgreSQL через PGlite с имитированной Auth-идентичностью; это не проверка живого Supabase или Google OAuth. Их нужно проверить отдельно после подключения проекта.
