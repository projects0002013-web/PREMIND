# Как сделать PREMIND доступным в поиске Google

Целевой адрес сайта: https://projects0002013-web.github.io/PREMIND/ . Это предполагаемый стандартный адрес GitHub Pages; доступность и фактическое завершение деплоя нужно проверить отдельно. Для индексирования Supabase не обязателен — локальные тесты работают без аккаунта.

## 1. Опубликовать сайт

GitHub → репозиторий PREMIND → Settings → Pages → Source: GitHub Actions. В Actions проверьте успешный workflow Build and deploy PREMIND. Откройте опубликованный адрес в обычном браузере без входа в GitHub: он должен отдавать страницу, а не 404 или запрос авторизации.

## 2. Подключить Google Search Console

1. Откройте https://search.google.com/search-console/ и добавьте ресурс **с префиксом URL**: `https://projects0002013-web.github.io/PREMIND/`.
2. Подтвердите владение через предлагаемый Google HTML-файл. Скачайте именно выданный файл и поместите его без изменений в `public/`, затем опубликуйте изменения. Например, выданный файл `google123.html` должен открываться по `https://projects0002013-web.github.io/PREMIND/google123.html` с оригинальным содержимым. Не создавайте произвольный файл с придуманным кодом.
3. Нажмите «Подтвердить» в Search Console. В качестве альтернативы Google может предложить настоящий meta-тег подтверждения; его можно добавить в `index.html` после получения.
4. В разделе Sitemaps отправьте `https://projects0002013-web.github.io/PREMIND/sitemap.xml`.
5. Через «Проверка URL» проверьте главную страницу и выберите «Запросить индексирование», если кнопка доступна.

Доступа к вашему Google Search Console у приложения и агента нет; добавление ресурса и подтверждение выполняет владелец Google-аккаунта. Эти действия не публикуют автоматически Google OAuth: настройка входа описана отдельно в CLOUD_SETUP.md.

## 3. Что уже добавлено в код

Русский заголовок и описание, canonical URL, Open Graph для ссылок, структурированные данные WebApplication, sitemap с публичной главной страницей, видимое описание тестов и их ограничений. Начальная HTML-страница содержит текст до запуска React; те же возможности описаны на главной странице приложения. Результаты пользователей и персональные страницы не перечисляются в sitemap. HashRouter использует фрагменты URL; их не нужно перечислять как отдельные индексируемые страницы.

На GitHub Pages проекта файл `public/robots.txt` оказался бы по адресу `/PREMIND/robots.txt`, а поисковые роботы читают `/robots.txt` в корне домена. Поэтому ложная настройка robots.txt в каталоге проекта не добавлялась: используются meta robots и отправка sitemap непосредственно в Search Console. Если у вас появится свой домен, настройте корневой robots.txt отдельно.

## 4. Когда сайт появится

Появление в выдаче и позицию определяет Google. Запрос индексирования не гарантирует включения в индекс или сроков; обработка может занять дни или недели, иногда дольше. Для начала проверяйте запросы «PREMIND» и «PREMIND проверка усталости». По общему запросу «проверка усталости» много конкурентов; первое место не гарантируется. Голосовой поиск использует обычную выдачу: специального правила, принудительно открывающего PREMIND по общей фразе, нет.

Помогают содержательная публичная информация о методике, ссылки со страницы проекта/школы и удобная работа на телефоне. Не используйте выдуманные отзывы, медицинские обещания или массовые искусственные ссылки. Отзывы и оценки в разметку не добавлялись.

Если изменится домен или путь размещения, обновите canonical, Open Graph и JSON-LD в index.html, sitemap.xml, Vite base, PWA manifest, redirect URL Supabase и ресурс Search Console.
